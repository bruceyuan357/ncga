# 操作规范审查 + 衍生标准提案

> **作者**: Opus 4.8 (1M) · **日期**: 2026-05-19
> **触发**: 用户从 Opus 4.7 切到 4.8,问"4.7 时期靠记忆/习惯的操作约定(8 条 dev 规则 + DRLI 预算)还适用吗"
> **任务**: ① 评估每条规范的理据是否成立 ② 基于理据的底层逻辑衍生新标准
> **裁决(用户已拍板)**: 原 8 条 + 新 8 条全部保留;落地为「混合机制 + 全局作用域」

---

## 0. 对 4.8 还适用吗?适用 —— 本 session 实证

切到 4.8 后,我**亲自违反了 Rule #3**:Chrome 扩展宣称"修好了"至少 6 次(default_locale 加载失败、改写无输出、右键浮窗不来、弹窗一闪而过、重复 attachShadow),每次都过了 `node --check`,每次用户在真 Chrome 里发现没用。

→ 这些规则防的不是"4.7 的毛病",是"在这个环境做这种活必然踩的坑"。模型换了,坑没换。

## 1. 框架:理据三源头

| 源头 | 换模型会失效吗 |
|---|---|
| 环境锚定(worktree GC、未提交即丢) | 不会 |
| 工程现实锚定(UI 要肉眼看、沉没成本、集成点出 bug) | 不会 |
| AI 行为锚定(爱营销、模糊指令硬冲、跳过反思) | 可能,但保留成本≈0 |

## 2. 8 条逐条裁决

| # | 规则 | 成立度 | 裁决 |
|---|---|---|---|
| 1 | 每<1h commit | 5 | 保留+强化(本 session 又抓到 1189 行未提交) |
| 2 | 后端先美学后 | 4 | 保留但**改理据**:美学非"最便宜重做"(这次改 6 轮最贵),真正理由是"最主观、要预期多轮" |
| 3 | 对的 artifact 上验证 | 5 | 保留+装牙齿(最常被违反 → 新 #11) |
| 4 | 失败2次换路 | 4 | 保留 |
| 5 | 测试同 commit | 4 | 保留 |
| 6 | 文档同 commit | 3 | 保留但约束力最弱(常单开 README commit) |
| 7 | 不过度营销 | 4 | 保留,本 session 守住 |
| 8 | 模糊+贵重做先澄清 | 5 | 保留,本 session 两次正面验证 |

**DRLI 预算**: 成立度 4,当前休眠 —— 最近都是"实时修 bug"(firefighting)非闭门 cycle。保留 + 标适用边界:deliberate cycle 启用,live firefighting 让位于"快速澄清+立即验证+小步提交"。

## 3. 新增 8 条衍生标准

| 新# | 标准 | 来源 | 触发事件 |
|---|---|---|---|
| 9 | 数据/产物也是代码,要提交 | #1 盲区 | lexicon 1189 行 import 了没 commit |
| 10 | 每 commit 立即 push | #1 推进 | 14h 灾难真因是 committed 也没 push |
| 11 ⭐ | 不能验证就标 UNVERIFIED,不许说"修好了" | #3 装牙齿 | 扩展 6 个 bug 都只验了语法 |
| 12 | API 字段对真实响应核验,不靠记忆 | #3 具体化 | data.text vs 真实 rewritten_text → 无输出 |
| 13 | 单元全绿 ≠ 集成边界能跑 | #3+#5 | 198 测试绿,6 个集成 bug 没测出 |
| 14 | 报喜连报"没验的部分" | #7 对称化 | 审计报告列了 WARN/FAIL |
| 15 ⭐ | 模型/上下文切换后重新验证,不继承信任 | #8 推广 | 本任务查出未提交数据+僵化测试 |
| 16 | 现场 bug 先变测试再变修复 | DRLI+#5 | 扩展 6 个 bug 修了零回归测试 |

⭐ = 实证价值最高。

## 4. 落地机制(混合 + 全局)

```
环境锚定 → hooks (~/.claude/settings.json,硬性强制):
  #1 commit · #9 commit-data · #10 push

工程现实锚定 → 部分 skills + 部分 CLAUDE.md:
  #3/#11 verify-before-claim (skill)
  #12 api-contract-check (skill)
  #13 integration-smoke (skill)
  #2/#4 → CLAUDE.md 常驻
  #5/#6 → hooks 提醒

AI 行为锚定 → skills + CLAUDE.md:
  #8 clarify-before-action (已存在的 skill)
  #15 re-verify-on-switch (skill)
  #7/#14 → CLAUDE.md 常驻
  DRLI → CLAUDE.md(标休眠/适用边界)
```

全部装到 `~/.claude/`(全局,所有项目继承)。

## 5. 关键洞察

用户原想法"全做成 skills 每个会话激活"有一处误解:**skills 是按相关性被模型调用的,没有"每会话强制加载"开关**。真正"常驻"的是 memory/CLAUDE.md;真正"强制"的是 hooks。所以最优解是三机制混合,各放最适合的层 —— 比 16 个 skill 严格更好。

且:这些原则**本就已在 NCGA 每个会话自动加载**(MEMORY.md → rules_8)。真正的缺口是 ① 全局作用域 ② 强制执行(非被动提醒)。故本轮落地重心是 global + hooks,不是 skill 本身。
